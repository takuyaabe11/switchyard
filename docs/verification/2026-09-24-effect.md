# switchyard の効果の実測(0.6.0)

## 環境

- 日時: 2026-09-24
- Linux(コンテナ)・論理コア 4・Node v22.22.2
- switchyard の容量は `SWITCHYARD_CAPACITY=4`

どの実験も、同じ機械で「素のまま同時に走らせる」場合と「switchyard を通す」場合を比べた。
スクリプトは下にそのまま載せる。

## 1. 計測の乱れ(`measure`)

固定量の計算(3 億回のループ)にかかった時間を測る小さなベンチを、5 回ずつ走らせた。

| 条件 | 所要(ms) |
|---|---|
| 単独 | 1380 / 1391 / 1376 / 1361 / 1394 |
| CPU を使う走行 4 本の横(素のまま) | 1732 / 2115 / 1979 / 1650 / 1746 |
| 同じ 4 本を switchyard の batch にし、ベンチを `--class measure` で走らせる | 1226 / 1254 / 1252 / 1293 / 1201(それぞれ約 3.9 秒待ってから走った) |

素のままでは、数字が 20〜50% 悪くなり、ばらつきも大きい。switchyard の `measure` は、先に走っていた 4 本が終わるまで待ち
(約 3.9 秒)、その後は単独と同じ水準の数字になる。数字が意味を持つ代わりに、待ち時間を払う。

## 2. CPU を使うテストの全件(完了までの時間)

4 本のスレッドで固定量を計算する「全件」(単独で約 4.0 秒)を、3 本同時に始めた。

| 条件 | 各走行が終わった時刻(始めてから) | 平均 | 最後 |
|---|---|---|---|
| 素のまま | 11.9 秒 / 11.9 秒 / 11.9 秒 | 11.9 秒 | 11.9 秒 |
| switchyard(`--cpus 4`) | 4.3 秒 / 8.4 秒 / 12.4 秒 | 8.4 秒 | 12.4 秒 |

CPU を取り合う走行では、全体の所要はほぼ変わらない(+4%。包みの起動と割り振りの往復の分)。一方で、先に始めた走行が
早く結果を返すので、平均の完了時間は約 30% 短くなる。エージェントは最初の結果で次の作業に移れる。

## 3. CPU をあまり使わないテストの全件(switchyard 自身の `npm test`)

switchyard 自身のテスト(483 件。子プロセスの起動と待ちが中心で、CPU はあまり使わない)を 3 本同時に始め、2 回繰り返した。

| 条件 | 全体の所要 | 落ちたテスト |
|---|---|---|
| 素のまま | 15 秒 / 15 秒 | 0 / 0 / 0、0 / 0 / 0 |
| switchyard(`--cpus 2..4`) | 25 秒 / 26 秒 | 0 / 0 / 0、0 / 0 / 0 |

CPU を取り合わない走行では、順番に並べると遅くなるだけで、得るものは無かった。この機械では同時に走らせても
落ちるテストは出なかった(負荷をさらに上げると `connect` のテストが落ちることは、別の実験で見ている)。

### 3'. 同じ実験を 0.7.0(実測で取り分を縮める)で

同じ全件を switchyard を通して 3 回単独で走らせ(平均 0.78 コア・割り振り 4 コア)、その後 3 本同時に始めた。

| 条件 | 全体の所要 | 落ちたテスト |
|---|---|---|
| switchyard 0.7.0(学んだ後。各 1 コアに縮めて 3 本同時に入場) | 19 秒 / 18 秒 | 0 / 0 / 0、0 / 0 / 0 |

この時点のテストは 494 件で、1 本を単独で走らせると約 16 秒。並べずに同時に入れるので、0.6.0 の 25 秒から
素のままに近い所要まで戻った。CPU を使い切る全件(平均 3.8 コア)は縮めず、宣言どおり 2..4 のまま入場した。

## 読み方

- switchyard が効くのは、CPU を取り合う走行(スレッドを使うテストランナー・ビルド・計測)が、同じ機械の複数のセッションから
  重なるとき。計測の数字を守り、先に始めた走行の結果を早く返す。
- 待ちと入出力が中心の走行を宣言どおりに並べると遅くなる。0.7.0 からは、実測で割り振りの半分も使わない profile の取り分を
  縮めて、並べずに入れる(3')。学ぶまでの最初の 3 回は宣言どおりに並ぶ。

## スクリプト

```js
// bench.js: 固定量の計算にかかった時間(ms)
const t0 = process.hrtime.bigint();
let x = 0;
for (let i = 0; i < 3e8; i++) x = (x + i * 7) % 1000003;
console.log(Number((process.hrtime.bigint() - t0) / 1000000n), x);

// burn.js: 引数の ms だけ CPU を使い続ける
const e = Date.now() + Number(process.argv[2] || 8000);
let y = 0;
while (Date.now() < e) y++;

// suite.js: 4 本のスレッドで固定量を計算する「全件」
const { Worker } = require('node:worker_threads');
const t1 = Date.now();
let left = 4;
for (let i = 0; i < 4; i++) {
  const w = new Worker(`let x=0; for (let i=0;i<4e8;i++) x=(x+i*7)%1000003; require('node:worker_threads').parentPort.postMessage(x)`, { eval: true });
  w.on('message', () => { if (--left === 0) { console.log(Date.now() - t1); process.exit(0); } });
}
```

```sh
# 1: 横に 4 本走らせたベンチ(素のまま / switchyard)
for j in 1 2 3 4; do node burn.js 4000 & done; sleep 0.3; node bench.js; wait
for j in 1 2 3 4; do switchyard run --cpus 1 -- node burn.js 4000 & done; sleep 0.3; switchyard run --class measure -- node bench.js; wait
# 2: 3 本同時の全件
for j in 1 2 3; do node suite.js & done; wait
for j in 1 2 3; do switchyard run --cpus 4 -- node suite.js & done; wait
# 3: switchyard 自身のテストを 3 本同時に
for j in 1 2 3; do npm test & done; wait
for j in 1 2 3; do switchyard run --cpus 2..4 -- npm test & done; wait
```
