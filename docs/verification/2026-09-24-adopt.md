# 0.10.0 の実測(取り分を道具に渡す・観察だけのモード・uninstall)

## 環境

- 日時: 2026-09-24
- Linux(コンテナ)・論理コア 4・メモリ 16GB・Node v22.22.2・Go 1.24.7・Python 3・pytest-xdist 3.8.0
- 前の実測: [2026-09-24-throughput.md](2026-09-24-throughput.md)

## 1. 道具が読む並列度の変数(配布物の中身で確かめた)

| 道具 | 変数 | 確かめ方 |
|---|---|---|
| Vitest 1〜3 | `VITEST_MAX_THREADS`・`VITEST_MAX_FORKS` | `npm pack vitest@1/2/3` の dist で、`poolOptions` の `maxThreads`/`maxForks` に入る |
| Vitest 5 | `VITEST_MAX_WORKERS` | `npm pack vitest@5` の dist で `resolved.maxWorkers` に入る |
| pytest-xdist 3.8 | `PYTEST_XDIST_AUTO_NUM_WORKERS` | `xdist/plugin.py` が `-n auto` の数として読む |
| Rust・Go・OpenMP | `CARGO_BUILD_JOBS`・`RUST_TEST_THREADS`・`RAYON_NUM_THREADS`・`GOMAXPROCS`・`OMP_NUM_THREADS` | 各道具の文書どおり |

Jest・Playwright・Gradle・Maven・make・dotnet には確かな変数が無いので渡さない(make の `MAKEFLAGS` は、並列を想定しない
Makefile を壊しうる)。

## 2. CPU だけを使う走行(go test)

24 本の並列のサブテストで固定量を計算する `go test`(単独で約 7.5 秒・約 4 コア)。横で、switchyard を通さない小さな計算
(単独で 1.25〜1.37 秒)を 3 回走らせた。

| 場面 | 並列度を渡さない | 渡す |
|---|---|---|
| 単独・既定の容量 3(4 コア − 予約 1) | go test 10.0 秒・横 1.46〜1.54 秒 | go test 9.8 秒・横 1.35〜1.47 秒 |
| `--cpus 2` を 2 本同時に(容量 4) | 16.3 / 16.3 秒・横 1.30〜1.41 秒 | 16.7 / 16.8 秒・横 1.35〜1.45 秒 |

最初は「割り当てたコア数」をそのまま渡していた。そのときの単独の場面は、go test が 9.4 秒から 10.4 秒に遅くなった
(予約の 1 コアを使えなくなった)。一方、横の計算は 3% ほどしか速くならなかった。テストの結果を待つ間、Claude Code は
ほとんど CPU を使わないので、予約のコアを空けておいても得るものが少ない。そこで、容量いっぱいを割り当てた走行
(機械を独り占めしている走行)には、機械の全コア数を渡すようにした。上の表はその後の数字。

CPU だけを使う走行では、分け合う場面でも差が出なかった。スレッドが多くても、OS がコアを公平に分けるため。

## 3. コアごとにワーカーを立てる走行(pytest -n auto)

各ワーカーが読み込み時に 150MB を確保するテスト 16 件を、容量 4 で `switchyard run --cpus 2 -- pytest -n auto` として走らせた。

| 条件 | ワーカー | ピークのメモリ(デーモンが測った RSS) | 所要 |
|---|---|---|---|
| 並列度を渡さない | 4 | 758MB | 3.3 秒 |
| 渡す | 2 | 396MB | 5.1 秒 |

利用者が 2 コアと宣言した走行が、2 コア分のワーカーとメモリに収まった。所要が延びたのは、宣言どおりの結果。
既定の表(`2..all`)で単独で走るときは、全コア数が渡るのでこうはならない。

## 4. 観察だけのモード(shim を通した実物)

shim を `PATH` の先頭に置き、`SWITCHYARD_OBSERVE=1` で、上の `go test` を 2 秒ずらして 2 本走らせた。

- デーモンは起動しなかった(記録の置き場には `observed.jsonl` だけ)。2 本は並ばずに同時に走った(全体 16 秒)。
- `switchyard report` の出力:

```
観察だけのモードの記録(switchyard は何も止めず、並べていない):
  重い走行 2 本(1 セッション)のうち、他の重い走行と重なった 2 本・重なっていた時間の合計 22秒
  他の重い走行の横で走った計測: 0 本
  同じ鍵(git の index・ポートなど)を持つ走行の重なり: 0 回
  PreToolUse が入れていれば: 拒否 0 件・重い走行として背景の候補 0 件
```

## 5. uninstall

`test/cli/uninstall.test.mjs` で確かめた。

- セッションの環境ファイル 2 つから、switchyard の shims の行だけが消える。他の plugin の shims の行と、他の行は残る。
- 記録の置き場が消える。`--keep-logs` なら残り、`--dry-run` なら何も変わらない。
- 置き場に switchyard のものでないファイルがあれば、何も消さない。
