# 変更なしの走り直しの計測(0.15.0)

## 目的

同じ重い走行を合流させたり、結果を使い回したりする機能を作る前に、それで減らせる仕事がどれだけあるかを、実際の記録で見積もる。

## 方法

`switchyard replay --dir /root/.claude/projects` を、switchyard を開発してきた Claude Code のセッションの記録に対して走らせた。
対象は、メインの記録 1 本とサブエージェントの記録 17 本。Bash の呼び出しは 747 件で、そのうち重い走行が 196 件。

同じ記録の中で、同じ cwd・同じコマンドの重い走行がもう一度走ったら「走り直し」と数える。ただし、間にファイルを書き換えうる操作を挟んだものは数えない。

- 厳しめ: 書き換えのツール(Edit・Write など)と、読むだけと言い切れない Bash を、書き換えうる操作とみなす。
- 緩め: 書き換えのツールだけを、書き換えうる操作とみなす。

## 結果

```
同じ状態での走り直し(重い走行 196 件のうち。間にファイルを書き換えずに、同じ場所で同じコマンドをもう一度)
  厳しめ: 1 件(0.5%)・前景の所要の合計 1秒
  緩め(Bash での書き換えは見ない): 1 件(0.5%)・1秒
  うち失敗の直後の走り直し: 1 件
    1 回・1秒  ./gradlew test
```

その 1 件も、権限の振る舞いを確かめる実験の中で、拒否された後に走らせ直したものだった。

## 読み方

- この記録では、合流と結果の使い回しで減らせる仕事は、ほぼ無い。重い走行はどれも、ファイルを書き換えた後に走っている。
- ただし、これは 1 人の(しかもエージェント自身が開発する)使い方の記録にすぎない。
  - 複数のセッションを並べる人の記録では違いうる。
  - 環境のせいで落ちたテストを直さずに走らせ直す人の記録でも違いうる。
- 合流と使い回しを作るかどうかは、利用者自身の記録で `switchyard replay` を走らせた結果で決める。
