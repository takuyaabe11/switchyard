# 環境のせいかもしれない失敗の見分け(0.12.0)

## 実行日時・環境

- 日時: 2026-09-24
- 4 コアの Linux(`uname -sr`: Linux 6.18.44-fc-v37)・`node --version`: v22.22.2
- 一時の `SWITCHYARD_HOME`・`SWITCHYARD_LANG=ja`

## 手順

`switchyard run --cpus 1..1 -- sh -c 'sleep 3; exit 1'`(3 秒走って失敗する走行)を、条件を変えて走らせた。

- A: 静かな機械
- B: switchyard を通さない `node -e 'for(;;){}'` を 4 本(全コア)走らせた横
- C: B と同じ条件で、成功する走行(`exit 0`)

## 結果

```
## A 静かな機械
[switchyard] 開始 jmufn5u2g0(CPU 1)
exit=1
## B switchyard の外で 4 コアを使う処理の横
[switchyard] 開始 jmufn5xow1(CPU 1)
[switchyard] この失敗はコードのせいではないかもしれない: 機械の 4 コアがほぼ全部使われ、そのうち約 3 コアは switchyard の外の処理が使っていた。コードを直す前に、機械が空いてから同じコマンドを走らせ直して確かめる(switchyard top で混み具合が見える)
exit=1
## C 同じ条件で成功する走行
[switchyard] 開始 jmufn61c62(CPU 1)
exit=0
## report
失敗した走行: 2 件(うち環境のせいかもしれない 1 件)  管理なしの走行: 0 件  抜けた子: 0 件
```

## 読み方

- 静かな機械での失敗には何も添えない(A)。成功した走行にも添えない(C)。
- switchyard の外の負荷も見える(B)。機械全体の使用コア数から、この走行に渡したスレッド数(ここでは 1)を引いた分を
  「他の処理」とみなすので、4 コアのうち約 3 コアが外の処理と出る。switchyard の他の重い走行と重なった場合は、その本数も添える
  (`test/daemon/diagnose.test.mjs`)。
- 機械を忙しくしているのがその走行自身だけなら(全コアを渡した走行が全コアを使う)、何も言わない。
- `switchyard report` は失敗のうち手がかりが付いた件数を数える。

手がかりは見立てで、診断ではない。忙しい機械でも、走行はそれ自身の理由で失敗しうる。だから Claude には「直す前に、空いてから
走らせ直して確かめる」とだけ伝える。

例・新しい道具の既定表と shim とふるい)がすべて赤になった。他の 10 組もすべて赤。
